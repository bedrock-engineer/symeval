# symeval — Agent Guide

## What it is

Python package extending sympy expressions with two methods for engineering calculations:

- `.sym_evalf()` — evaluates with `pint` quantities and renders a three-step LaTeX chain: symbolic → numbers with units → result. Returns a `SymbolicEvaluation` with `_repr_latex_`.
- `.quantity_evalf()` — same unit-aware evaluation, no LaTeX overhead. Useful inside `DataFrame.with_columns(...)` to compute a new column row-by-row. Returns a `pint.Quantity`.

Built on sympy + pint. Rendering via `_repr_latex_()` so it works in both marimo and Jupyter without a marimo runtime dependency.

## Source layout

Notebook-as-source using mobuild (like koaning/hastyplot):

- **`symeval_mo.py`** — marimo notebook; single source of truth for all library code, tests, and feature examples. Cells marked `## EXPORT` get extracted into the package.
- **`src/symeval/__init__.py`** — auto-generated by mobuild. **Do not edit.**
- **`examples/`** — standalone marimo demo notebooks.

## Commands

Tasks are defined in `[tool.taskipy.tasks]` in `pyproject.toml` and run via taskipy (a dev dependency).

```bash
uv sync --group dev          # install dev deps (taskipy, pytest, polars)
uv run task install          # alias for uv sync --group dev
uv run task build            # mobuild export: extracts EXPORT cells into src/symeval/__init__.py
uv run task test             # runs tests: pytest symeval_mo.py with marimo deps
uv run task release 0.2.0    # bumps version, commits, tags, pushes, creates GitHub release
uv run task pypi             # builds wheel and publishes to PyPI
```

### Release workflow

See `RELEASING.md` for full details. Tests run inside `release` (before tagging), not in `pypi`. The tag is the trust boundary — once a tag exists, the code is tested. Version lives only in `pyproject.toml` (no `__version__` attribute).

## Conventions

- All library code and tests live in `symeval_mo.py`. Test functions defined inside cells (`def test_*`) are discovered by pytest running against the notebook.
- Use `## EXPORT` markers for cells that should be extracted into the package.
- No `__version__` attribute at runtime — use `importlib.metadata.version("symeval")`.
- Units use `pint`, not `sympy.physics.units`.
- No bundled `UnitRegistry` — derived from user's pint quantities (`q._REGISTRY`). Empty-subs falls back to `pint.get_application_registry()`. Users create quantities with `pint.Quantity` (or their own `UnitRegistry`); the result lands in their registry.
- Rendering via `_repr_latex_()` — works in marimo and Jupyter without a marimo runtime dependency.
- Keep the package minimal.

## Claude Code & OpenCode dual setup

This repo has both `AGENTS.md` (OpenCode) and `CLAUDE.md` (Claude Code). `CLAUDE.md` is a one-liner that imports `AGENTS.md` via `@AGENTS.md`, so `AGENTS.md` is the single source of truth for agent instructions.

To keep tooling in sync:

1. **Permissions** — OpenCode reads `opencode.json` (repo root), Claude Code reads `.claude/settings.local.json`. If you use both tools, create `opencode.json` mirroring the allowed patterns from `.claude/settings.local.json`.
2. **Skills** — OpenCode discovers skills from the paths listed in the system prompt. The marimo-related skills (`marimo-notebook`, `marimo-pair`) are built-in. No additional setup needed unless you install new skills — then ensure they're available in both tools' skill paths.
